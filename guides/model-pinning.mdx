---
title: "Pin your Nyckel function to a specific model version"
sidebarTitle: "Model Pinning"
description: "Use model pinning to lock your invoke endpoint to a specific trained model version, enabling testing before switching to new models."
---

When you add new training data, Nyckel automatically retrains and redeploys your function so the `/invoke` endpoint always uses the most recent model. This is convenient for most use cases, but sometimes you need more control — for example, when you want to run integration tests or other checks before promoting a new model version to production.

Model pinning lets you invoke a specific model version by passing a `modelId` query parameter. The standard `/invoke` endpoint continues to serve the latest model; pinned invocations bypass that and target the exact version you specify.

<Note>
  Your project must be enabled for model pinning before you can use this feature. Contact [feedback@nyckel.com](mailto:feedback@nyckel.com) to enable it on your account.
</Note>

## Find your model ID

Projects enabled for model pinning display a **Model Info** panel on each function page. This panel appears at the bottom of the right-hand column, below the label bars.

Copy the value labeled **Model Id** — this is your `modelId`.

## Invoke with a pinned model

To target a specific model version, append `?modelId=<modelId>` to your invoke URL.

<CodeGroup>

```bash curl
curl -X POST \
  -H 'Authorization: Bearer <accessToken>' \
  -H 'Content-Type: application/json' \
  -d '{"data":"<inputData>"}' \
  'https://www.nyckel.com/v1/functions/<functionId>/invoke?modelId=<modelId>'
```

```python Python
import requests

url = 'https://www.nyckel.com/v1/functions/<functionId>/invoke?modelId=<modelId>'
headers = {
    'Authorization': 'Bearer ' + '<accessToken>',
}

result = requests.post(url, headers=headers, json={"data": "<inputData>"})
print(result.text)
```

```javascript JavaScript
fetch('https://www.nyckel.com/v1/functions/<functionId>/invoke?modelId=<modelId>', {
  method: 'POST',
  headers: {
    'Authorization': 'Bearer ' + '<accessToken>',
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({ data: '<inputData>' })
})
  .then(response => response.json())
  .then(data => console.log(data));
```

```php PHP
$ch = curl_init();

curl_setopt($ch, CURLOPT_URL, 'https://www.nyckel.com/v1/functions/<functionId>/invoke?modelId=<modelId>');
curl_setopt($ch, CURLOPT_RETURNTRANSFER, 1);
curl_setopt($ch, CURLOPT_POST, 1);
curl_setopt($ch, CURLOPT_POSTFIELDS, '{"data":"<inputData>"}');

$headers = [];
$headers[] = 'Authorization: Bearer ' . '<accessToken>';
$headers[] = 'Content-Type: application/json';
curl_setopt($ch, CURLOPT_HTTPHEADER, $headers);

$result = curl_exec($ch);
curl_close($ch);
echo $result;
```

</CodeGroup>

<Tip>
  A typical workflow is to pin your staging or CI environment to a known-good model ID, then update the pinned version only after your integration tests pass against the new model.
</Tip>
